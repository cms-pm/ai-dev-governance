# R-8.2-05 — Cross-Phase Closure Request (Phase 8.3 → Phase 8.1)

**Risk ID:** R-8.2-05
**Owning phase:** Phase 8.2 (originating); Phase 8.3 (closure-driver per
OPP-8.2-003).
**Dependent phase:** Phase 8.1.
**Anchor SHA:** `5d47359` (SCN-8.2.2 adoption commit — Power of 10
discipline adopted in `core/CODE_IMPLEMENTATION_COMPLEXITY_GOVERNANCE.md`).
**Authored by:** SCN-8.3.1.
**Status:** Open — closure depends on bidirectional protocol completion;
Phase 8.3 cannot unilaterally close.

---

## Why this packet exists

Phase 8.2 adopted the Power of 10 universal clauses against the
`5d47359` bar-shift anchor and introduced an explicit
§Cross-Phase In-Flight Coordination clause to coordinate with the
Phase 8.1 in-flight cohort. R-8.2-05 captures the residual closure
debt: the clause is in force on `main`, but the reciprocal
acknowledgement on the Phase 8.1 side has not yet landed, and each
Phase 8.1 chunk branch's merge-time analyzer disposition is not yet
known.

This packet is the Phase 8.3-owned artifact that drives R-8.2-05 to
closure. It restates the closure criterion verbatim from
`docs/planning/phase-8.2-risks.md`, identifies the verification
surface, and defines the sprint-critique cadence Phase 8.3 will run
until both halves of the criterion are satisfied.

## Closure criterion (verbatim from `docs/planning/phase-8.2-risks.md` R-8.2-05)

R-8.2-05 flips from **open** to **closed** only when both halves of the
following criterion are satisfied:

- **(a) Reciprocal entry.** `docs/planning/phase-8.1-risks.md` on `main`
  contains an entry citing R-8.2-05 and SHA `5d47359`, with mitigation
  acknowledging the Power of 10 acceptance bar on next post-adoption
  touch.
- **(b) Per-branch analyzer disposition.** Each Phase 8.1 chunk branch
  merges to `main` carrying either (b.i) a clean analyzer pass on
  touched files, or (b.ii) an explicit
  `core/EXCEPTIONS_AND_WAIVERS.md` entry covering the touched files.

Either half alone is insufficient. Phase 8.3 records the disposition
of each half independently in its sprint critiques.

## Verification hook

Cadence and surface:

- **Cadence.** Every Phase 8.3 sprint critique runs the verification
  hook. (Sprint critique cadence is set by Phase 8.3's review window
  for R-8.3-04 in `docs/planning/phase-8.3-risks.md`.)
- **Surface (a).** Read `docs/planning/phase-8.1-risks.md` on `main` and
  search for an entry that names both `R-8.2-05` and SHA `5d47359`.
  Presence of such an entry satisfies half (a).
- **Surface (b).** For each Phase 8.1 chunk branch that has merged to
  `main` since the prior sprint critique, read the merge commit and
  inspect either (b.i) the analyzer evidence linked from the commit,
  or (b.ii) the `core/EXCEPTIONS_AND_WAIVERS.md` rows whose scope
  intersects the merged files. Record the disposition per branch in
  the sprint critique notes.
- **Closure action.** R-8.2-05 flips to closed in
  `docs/planning/phase-8.2-risks.md` (and the carry-forward row in
  `docs/planning/phase-8.3-risks.md` is moved to the Closed-Risks
  table) only when **both** halves are satisfied for the full Phase 8.1
  in-flight cohort. Partial satisfaction MUST NOT be recorded as
  closure.
- **No unilateral closure.** Per OPP-8.2-003, Phase 8.3 owns
  closure-**driving**, not unilateral closure. If half (a) is missing,
  Phase 8.3 raises it with the Phase 8.1 owners but does not author the
  reciprocal entry on Phase 8.1's behalf.
